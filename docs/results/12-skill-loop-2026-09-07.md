# 12 — The skill-improvement loop, 2026-09-07: one change proposed, measured, and refuted

Artifact: **EXL3 turboderp SC 4.0bpw H5 @ 262,144** (cell A, the primary), one boot,
`--effort medium`. Task `code2` (`fixtures/code-task-2`, the ledger fixture). Twenty paired
cells, arms alternated every round so a drift cannot favour one side. Raw data:
`qwen38-tuning/results/quality-2026-09-07-loop/`.

**The headline is a refutation, and it is the useful part.** The change looked like a
success on the gate and is worse on the property the gate was standing in for.

---

## 1. The change under test

`qwen38-code-gate` check 6 is *"RED before GREEN — paste the failing line from before you
changed the source"*. The hypothesis: **check 6 is placed where it cannot be acted on.**
The skill is a "run this before you say it is finished" gate; five of its six checks are
genuinely post-hoc, and check 6 alone requires an action taken earlier. By the time the
model reads it, the source exists and the only honest answer left is the escape hatch.

`qwen38-code-gate-v2` is that file with **one** change: a step **0.5**, before the first
edit, telling the model to write the test and run it RED *now*. Everything else is
byte-identical.

## 2. What the gate said

| arm | `red_then_green` | gate score | mean wall | mean output tokens |
|---|---|---|---|---|
| `codegate` (current) | 7/10 | 4/5 ×3, 5/5 ×7 | 5.0 min | 11,728 |
| `codegate2` (+ step 0.5) | **9/10** | 4/5 ×1, 5/5 ×9 | 5.5 min | 13,564 (**+16 %**) |

Fisher one-sided **p = 0.29**. On its own this is "directionally better, not demonstrated".

**At n = 5 it read 5/5 against 3/5 and looked like a win.** Continuing to n = 10 removed
it. A five-rep pairing of a binary that sits near 70–90 % cannot separate these arms, and
the 2026-09-05 baseline used three.

## 3. What `red_then_green` actually measures — and it is not TDD

**In all twenty runs, both arms, the model wrote `parse.py`, `report.py`, `__init__.py`
and `README.md` before its first line of test.** The edit order is identical across arms:

```
turn 13  parse.py     turn 22  README.md
turn 16  report.py    turn 25  test_ledger.py
turn 19  __init__.py  turn 27  test_ledger.py
```

`red_then_green` asks only whether *some* test run failed before a later one passed. That
is what ordinary iteration looks like whenever the first implementation is buggy. It is
true 7–9 times in ten while the discipline it names happened zero times in the order the
skill asks for.

So the metric everything was being judged on is a **check that passes for a reason
unrelated to the property** — the third detector fault found in this repo today, after
CORRECTIONS 48 and the void-scoring fault.

## 4. The order, measured — and the ranking inverts

`tdd_order()` reports the turn of the first test **run** and of the first **source** edit
(a test file is not source; neither is a `README`, or a run that documented first would be
failed unfairly).

| set / arm | n | **tested before touching source** | `red_then_green` |
|---|---:|---:|---:|
| 09-07 `codegate` | 10 | **5/10** | 7/10 |
| 09-07 `codegate2` | 10 | **1/10** | 9/10 |
| 09-05 `codegate` | 3 | 0/3 | 1/3 |
| 09-05 `family` | 3 | 1/3 | 2/3 |
| 09-05 `noskill` | 3 | 0/3 | 0/3 |

**The current skill beats the variant 5/10 to 1/10, Fisher one-sided p = 0.070** — the
stronger of the two signals, and the opposite ranking to the gate score.

In `codegate2` the first source edit is consistently *early* (turn 13–24) and the first
test edit *late* (turn 25–50). Adding an instruction to test first appears to have pushed
test-writing later. **Why is not established** — the extra section also made the file
longer and the model spent 16 % more tokens — and one measured refutation does not need a
mechanism to stand.

**Verdict: `qwen38-code-gate-v2` is not shipped.** It is kept only as this record.

## 4b. A second variant, aimed at the mechanism — also refuted

The edit order in all 20 runs matched the **brief's own enumeration**, and the brief
(`fixtures/code-task-2/BRIEF.md`) names the test last:

> fix the bug · add `top(entries, n)` · update the README · **write tests and run pytest**

So `qwen38-code-gate-v3` is the *original* file plus one short line: *"The brief's list
order is not your build order … the test for a change, run and failing, then that
change."* Short on purpose, since v2's extra length was a candidate cause.

**Final, all three arms, same artifact, same boot, alternated:**

| arm | n | **tested before touching source** | `red_then_green` | mean output tok |
|---|---:|---:|---:|---:|
| `codegate` — untouched | 15 | **6/15 (40 %)** | 10/15 | 13,299 |
| `codegate2` — + step 0.5 | 10 | **1/10 (10 %)** | 9/10 | 13,564 |
| `codegate3` — + reorder line | 4 | **0/4 (0 %)** | 1/4 | 12,578 |

**Both attempts to instruct test-first made this model less likely to test first.**

Neither comparison reaches significance on its own — `codegate` vs `codegate2`
**p = 0.12**, vs `codegate3` **p = 0.18**. Pooling the two variants gives **p = 0.049**,
but **that pooling was chosen after seeing the data** and is therefore suggestive, not a
result. The argument that carries weight is not the p-value: it is that **two independent
interventions, one long and one short, both moved the metric the same wrong way**, and
neither moved it the intended way in a single run out of fourteen.

**Neither variant is shipped.** `qwen38-code-gate` stays as it is.

## 4c. What that leaves

The loop tested *where the instruction sits* (v2) and *what it says about ordering* (v3).
Both failed. What has not been tested, and is the obvious next slice:

- **Removing** check 6 rather than adding to it — every variant so far made the file
  longer, and the untouched file is the best performer.
- Changing the **brief** instead of the skill, to establish whether the brief's order is
  in fact what drives the edit order. That is the mechanism claim in §4b and it is
  **inferred from a correlation across 20 runs, not tested.**
- A task whose brief names the test *first*, as the control that claim needs.

## 4d. A slash token in a `-p` prompt is not a way to load a skill

Found while opening a GPU-free path on the 9arm gateway (cell D, `vllm/Qwen/Qwen3.8-27B-FP8`).

The `family` arm's brief ends `| /using-qwen38`. On EXL3 4.0bpw that produces **4 `Skill`
calls in every rep**. On the gateway it produced **0**, in both runs — so those cells
measured nothing whatever about skills, while still returning a gate score.

It is not a registration problem. Both streams' `init` events list the **same 48 slash
commands**, including all four qwen ones, and `Skill` is in `tools` on both. Asked in
words — *"ใช้ Skill tool โหลด qwen38-code-gate แล้วบอกชื่อหัวข้อแรก"* — the gateway model
calls `Skill` and quotes the file's first heading correctly.

So the token is the part that does not carry, and **which endpoint you point the harness at
decides whether an arm tests a skill at all.** Cells now carry `skills_explicit`; where it
is set, the brief names the tool and the skills instead of relying on the token. A and C
keep the token so the 2026-09-05 baseline stays comparable — **an arm on D is therefore not
the same arm as on A**, which is why the flag lives on the cell rather than on the arm.

Verified after the change: `D-code2-family-r2` → `Skill` ×4, a `THINK:` line, a `CODE GATE`
line, 5/5, and `tested_before_source_edit: True`.

## 5. Cross-boot caution

09-05 `codegate` is 0/3 tested-first; 09-07 `codegate` is 5/10. Same skill, same artifact,
same task, different day. The two sets are **not pooled** anywhere above, and the 09-07
comparison is same-boot and alternated, which is the only reason it is quoted at all.

## 6. What this changes

- `tdd_order` is now computed by `code_gate` on every code cell, beside `red_then_green`;
  the old field is kept so the 09-05 baseline stays comparable, and it is not to be read as
  a TDD measure again.
- **A binary pairing at n = 3 cannot answer a skill question** at these rates. Any future
  skill A/B on a near-ceiling binary needs either many more reps or a continuous metric;
  the turn indices above are the continuous one.
- The step-0.5 hypothesis is refuted **as written**. What has not been tested is whether a
  *shorter* skill, or one that removes check 6 rather than adding to it, moves the order.

## 7. Guards

the test-run detector (a `Read` of a file containing `ValueError` is not a test run), six
pin the void rules, and the rest pin the remote cell. All were red before their fix.
