# 18 - Thai repair: the 40 -> 0 / FP 0 verdict is retracted

Question: can a lightweight post-step repair malformed Thai without changing
correct Thai, code, JSON, paths, URLs, or tool payloads? The source material is
the same two captured YT Downloader sessions used by the original experiment:
`096ebcae` (EXL3) and `3258ccec` (FP8).

## Correction

The original 49-pair `dict v2` result -- **40 detector hits -> 0, FP 0** -- is
invalid as a shipping verdict. Its `rows_worse` metric counted only whether eleven
known broken patterns increased. It did not compare output with expected text,
so it could not see new corruption outside that list.

The old substring regex changes correct Thai, including:

| raw | old output |
|---|---|
| `ไฟล์` | `ไฟล์์` |
| `เว็บไซต์` | `เว็บไซต์์` |
| `โปรเจกต์` | `โปรเจกต์์` |
| `หรือ` | `หรืออ` |
| `ลิงก์` | `ลิงก์์` |
| `โฟลเดอร์` | `โฟลเดอร์์` |

There are 23 such correct-target occurrences in the two source sessions. The
same regex changes 172 entries in PyThaiNLP's 62,101-word `thai_words()` corpus.
The old counter still calls those rows no worse.

## Precision-first replay

The corrected experiment keeps only 29 malformed forms that are not substrings
of any known correct `thai_words()` entry. It also leaves fenced and inline
Markdown code, URLs, Windows paths, JSON documents, and tool payloads unchanged.

| source | rows | repairable occurrences | changed rows | old detector before -> after |
|---|---:|---:|---:|---:|
| `thai-session-20260916-024231.jsonl` | 43 | 68 | 23 | 36 -> 22 |
| `thai-session-20260916-042801.jsonl` | 7 | 11 | 4 | 4 -> 2 |

Every selected occurrence is removed by the post-step. The clean-word gate is
**0 changed of 62,101 known words**. Neither number proves precision on arbitrary
prose: the raw occurrence artifact explicitly records
`precision_claim: not_measured_without_independent_gold`. It is stored at
`qwen38-tuning/bench/results/thai-repair-safe-20260916.jsonl` with source,
block, offset, raw context, repaired context, and the applied rule.

The CLI now refuses empty input or rows without explicit `expected` text. For a
gold evaluation it emits raw, expected, and repaired text per arm instead of
summary-only rows.

## Float-token ban withdrawn

The proposed unconditional ban on 21 mark-only Thai token IDs is unsafe. On the
real 4.0 bpw tokenizer, 26,875 of the 62,101 known Thai words encode with at
least one of those IDs. A mark-only token may be an invalid start and still be
a valid continuation after a base consonant. The ban is not present on this
branch, and a serving regression test keeps those tokens available.

## Current verdict

- The old `dict v2` ship verdict is **RETRACTED**.
- The 29-rule precision-first subset is an offline candidate, not a served fix.
- The 20 ambiguous rules return raw text instead of guessing; this is why the
  old detector remains at 22 + 2 rather than zero.
- The repair is not wired into streaming serving. Streaming needs a separate
  integration design that preserves chunk boundaries and tool calls.
- Normalizer, Norvig spell correction, SymSpell, segmentation, WangchanBERTa,
  and Typhoon verdicts are unchanged by this correction.

The sampler sweep described elsewhere ran on profile F, not profile G. No
sampler arm ships from this experiment.
