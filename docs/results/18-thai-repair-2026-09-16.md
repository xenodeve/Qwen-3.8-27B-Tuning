# 18 - Thai repair: algorithm-only, dict v2 goes 40 to 0

Question: can a lightweight algorithm repair Thai script errors after the
primary model, without a second model? Regimes: two real Claude Code YT
Downloader sessions -- `096ebcae` (EXL3 4.0bpw via profile G: 43 blocks /
5,586 Thai chars / 36 broken, missing-vowel class) and `3258ccec` (FP8 via
9arm gateway: 7 blocks / 25,713 Thai chars / 4 broken + a ~24KB `บริบ`
syllable loop, doubling class). Plus a live 8-arm run on G (168 requests,
7 arms x 8 topics x 3 rounds) and an FP8 probe via 9arm (1,633 Thai chars).

## Numbers

Offline eval on the 50 session blocks (`tools/thai-eval-offline.py`,
`ms_cpu_poststep_row` is CPU-only post-step cost per block -- independent of
the serving ctx, NOT model latency):

| arm | session 1 (36 broken) | session 2 (4 broken) | rows worse (FP) |
|---|---:|---:|---:|
| raw | 36 | 4 | -- |
| normalize | 34 | 4 | 0 |
| **dict v2 (49 pairs)** | **0** | **0** | **0** |
| symspell (maxed=1, d<=1, allowlist) | 36 | 4 | 0 |
| spell (Norvig) | recall ~1/7, FP on clean Thai/code, ~2.9 s/sentence | -- | REJECT |

dict v2: 16 + 3 rows fixed, 0 worsened, ~0.02 ms CPU per block. SymSpell
adds nothing under the dict (its winnable pairs are a subset). FP8 probe:
0/1,633 on short regimes -- consistent with "quant amplifies, not causes".

## verdicts per algorithm

1. **normalizer** (`normalize`/`remove_repeat_vowels`, pythainlp 5.3.7): no
   effect on missing vowels (208 rows: broken 2 -> 2, 0 fixed). The 121
   changed rows are blank-line collapses, not repairs. Not shipped; kept as
   the `thai-normalize-ab.py` gate pinning the answer.
2. **NFC**: canonicalizes, never dedups (`ดีีี` unchanged). Not a repairer.
3. **dict v2**: SHIP candidate -- 40 -> 0, FP 0, ~0.02 ms. Every fixed form
   grounded in `thai_words()` (62k) except ให้คุณฟัง/ไม่มี (verified by hand).
   Regex longest-first so shadow pairs (`ไฟล` in `ไฟลล`) are safe.
4. **spell (Norvig)**: REJECT -- `วดีโอ` -> `วดี/มีดโอ`, `ไฟล์` -> `ไมล์`,
   `เกี่ยวกับ` -> `เกี่ยวพัน`, space/digits -> `กา`; ~2.9 s/sentence.
5. **SymSpell (TNC 106k)**: CONDITIONAL -- maxed=1, accept d<=1, allowlist,
   return raw on unknown; ~2/7 pairs, FP 0, 0.03-0.06 ms/word. Redundant
   under dict v2 today; kept as fallback.
6. **segmentation/Viterbi**: PARKED -- newmm+OOV ~107 ms/sentence passes
   budget but TNC vocab mismatches `thai_words` (correct words flagged OOV)
   and the implement is hundreds of lines for defects dict already covers.
7. **second model (Typhoon-CPU)**: PARKED -- no remaining defect justifies
   the serve cost after dict v2 (one leftover class in v1 closed by v2).
8. **LoopGuard + float-ban**: loops of every observed shape trip
   (U+0E48 micro, think-sentence, `บริบ` period-4 at char 574 of 24,508 --
   replayed). Float-mark ban (21 ids, zero overlap with Han, correct Thai
   untouched) in `cjk_guard.py`, awaiting one G restart.

## What this does not say

dict v2 covers the two observed sessions; a new malformed word needs a new
pair (recall ceiling is structural -- hapax 87% of distinct tokens). The
pipeline returns raw when no arm fires, so uncovered defects pass through
unchanged rather than corrupted. Live G 168-request run: base rate ~0 on
the short multiturn harness, so no sampler arm ships (falsifier held).

Falsifier for the ship: any correct-Thai/code corruption, or rows_worse > 0
on a new session, reverts the dict to the pair list that last measured clean.
