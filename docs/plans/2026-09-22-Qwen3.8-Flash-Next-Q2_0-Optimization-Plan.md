# Qwen3.8-Flash-Next GSQ-RCO Q2_0 — Dual-GPU Optimization Plan

## 0. Objective

ทดสอบและหา configuration ที่ดีที่สุดสำหรับรัน:

- **Model:** `ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-GGUF`
- **Quant:** `Q2_0`
- **Backend:** `llama.cpp / llama-server`
- **Primary use case:** Coding Agent ผ่าน OpenAI-compatible API
- **Primary OS:** Windows 11

เป้าหมายหลัก:

1. ใช้ context ได้สูงสุดเท่าที่ practical โดยเริ่มจาก **261,888 tokens**
2. ใช้ **Q4 KV cache**
3. จำกัด **Total Dedicated VRAM รวมทั้งระบบ <= 25.5 GB**
4. **26.0 GB เป็น absolute ceiling**
5. หลีกเลี่ยง Shared GPU Memory spill
6. รักษา RAM headroom ให้เพียงพอ
7. Optimize โดยยึดผลวัดจริง ไม่เดา
8. สร้าง profile อย่างน้อย 3 แบบ:
   - Max Context
   - Daily Coding
   - Max Speed

# 1. Hardware Ground Truth

ให้ใช้ข้อมูลต่อไปนี้เป็น baseline ของเครื่อง

## CPU

- Intel Core i5-13500
- 6 P-Cores + 8 E-Cores
- 14 Cores / 20 Threads

## Motherboard

- ASUS TUF GAMING B760M-PLUS WIFI

PCIe topology ที่ต้องคำนึง:

- GPU หลัก: สล็อตจาก CPU
- GPU รอง: สล็อตล่างของบอร์ด
- Agent ต้องตรวจ link width / link speed จริงก่อนเริ่ม benchmark
- ห้าม assume topology จากชื่อสล็อตเพียงอย่างเดียว

## RAM

- KLEVV CRAS V RGB ROG CERTIFIED
- 48 GB DDR5
- 7200 MT/s
- Measured memory bandwidth ประมาณ **108 GB/s**

## GPU

- NVIDIA GeForce RTX 4070 SUPER — 12 GB
- NVIDIA GeForce RTX 5060 Ti — 16 GB
- Total Dedicated VRAM = **28 GB**

## Measured Windows Background VRAM

หลังอัปเดต NVIDIA Driver:

- ปกติ background VRAM รวมอยู่ประมาณ **1.0–1.5 GB**
- ในอดีตอาจขึ้นได้ประมาณ 2–2.5 GB

ดังนั้น policy สำหรับการทดลอง:

```text
Preferred total dedicated VRAM usage <= 25.5 GB
Absolute ceiling                   <= 26.0 GB
Do not intentionally optimize toward 27–28 GB
```

เป้าหมายคือเหลือ headroom ให้ Windows, driver, CUDA workspace และ transient allocation

# 5. Main Performance Targets

## VRAM

```text
PASS       <= 25.5 GB total dedicated VRAM
BORDERLINE > 25.5 GB and <= 26.0 GB
FAIL       > 26.0 GB
```

## Shared GPU Memory

Shared GPU Memory ต้องใกล้ baseline

ถ้าเพิ่มจาก idle มากกว่า:

```text
~512 MB
```

ให้ mark config เป็น suspicious และตรวจ WDDM spill

## RAM

Preferred idle RAM ก่อนโหลด model:

```text
<= 16–18 GB used
```

หากก่อนเริ่มใช้ RAM อยู่ประมาณ 24–25 GB:

- บันทึกไว้
- แจ้งว่า benchmark อาจ受到 memory pressure
- ห้ามสรุปว่า prefill ต่ำเป็นข้อจำกัดของ model โดยไม่ตรวจ pagefile / page cache

## System Commit

หลีกเลี่ยง:

```text
> 90–92% committed memory
```

หากมี sustained pagefile thrashing ให้หยุด run

# 6. Why RAM Matters

ประมาณคร่าว ๆ:

```text
CPU MoE 25–26 layers
→ อาจใช้ RAM สำหรับ expert weights หลายสิบ GB
```

ดังนั้น RAM pressure สำคัญมาก

ก่อน benchmark:

- ปิดเกม
- ปิด VM
- ปิด application ที่ใช้ RAM สูงโดยไม่จำเป็น
- ลด browser tabs ถ้าใช้ RAM มาก
- ไม่จำเป็นต้องปิดโปรแกรมเบา ๆ เพียงเพื่อทำตัวเลขสวย

เป้าหมายคือให้ benchmark สะท้อน daily-use ได้ แต่ไม่ถูก pagefile กดจนผลเพี้ยน

# 37. Decision Rules


- VRAM ต่ำกว่า

- TTFT เสถียรกว่า
- Shared GPU Memory ต่ำกว่า
- Coding Agent loop เสถียรกว่า

ถ้าต่างกัน:

```text
> 5–8%
```
